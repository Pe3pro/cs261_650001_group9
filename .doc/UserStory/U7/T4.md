# U7:T4 Development

## User Story

U7: เจ้าหน้าที่และนักศึกษาตรวจสอบข้อมูลและสถานะการฝึกงาน/สหกิจศึกษา

## เป้าหมาย

พัฒนาระบบติดตามสถานะนักศึกษาตั้งแต่ยังไม่ยื่นใบสมัคร การตรวจคำร้อง การจับคู่บริษัท การเตรียมฝึกงาน เริ่มฝึกงาน จนถึงเสร็จสิ้นหรือยุติการฝึกงาน

งานประกอบด้วย:

- UI สำหรับเจ้าหน้าที่และอาจารย์
- UI สำหรับนักศึกษา
- REST API จำนวน 11 Endpoint
- DTO, Service, DAO และ Entity สำหรับข้อมูลการฝึกงาน
- ประวัติการเปลี่ยนสถานะ
- การกำหนดสิทธิ์ตาม Role
- การแจ้งเตือนสถานะที่ต้องดำเนินการ
- Event Integration ระหว่าง U6 และ U7
- Demo Seeder สำหรับ System Test และ UAT
- Unit Test สำหรับ UI, Controller, Service และ DAO

## Stage ของนักศึกษา

ระบบคำนวณ Stage จาก Application, Match และ Internship

| Stage | เงื่อนไข |
|---|---|
| `NOT_APPLIED` | ยังไม่มีใบสมัคร |
| `APPLYING` | กำลังยื่นหรืออยู่ระหว่างตรวจคำร้อง |
| `WAITING_MATCH` | คำร้องผ่านแล้วแต่ยังไม่มีผลจับคู่ |
| `MATCHING` | มีผลจับคู่แต่ยังไม่ได้ยืนยันสิทธิ์ |
| `READY` | ยืนยันสิทธิ์แล้วและมี Internship สถานะ `NOT_STARTED` |
| `IN_PROGRESS` | กำลังฝึกงาน |
| `COMPLETED` | ฝึกงานเสร็จสิ้น |
| `REJECTED` | คำร้องไม่ผ่าน |
| `TERMINATED` | การฝึกงานถูกยุติ |

## Attention Flags

| Attention | เงื่อนไข |
|---|---|
| `NO_MATCH` | ใบสมัครผ่านแล้วแต่ยังไม่มีผลจับคู่เกินเวลาที่กำหนด |
| `NOT_CONFIRMED` | นักศึกษายังไม่ยืนยันผลและเลย `confirmDeadline` ของรอบ |
| `MISSING_INFO` | ข้อมูลวันที่หรือผู้ดูแลการฝึกงานไม่ครบ |
| `START_OVERDUE` | เลยวันเริ่มฝึกงานแต่สถานะยังเป็น `NOT_STARTED` |

เดิม `NOT_CONFIRMED` ตรวจจากวันที่จับคู่เกิน 7 วัน แต่ได้แก้ให้ตรวจจาก `MatchingRound.confirmDeadline` ตามข้อตกลง S9 ของ U6

กรณีเวลาปัจจุบันตรงกับ `confirmDeadline` พอดียังไม่ถือว่าเลยกำหนด ต้องเป็นเวลาหลัง `confirmDeadline` เท่านั้น

## U6 และ U7 Event Integration

เมื่อกดยืนยันสิทธิ์ใน U6:

1. `MatchingService` เปลี่ยน Match จาก `PROPOSED` เป็น `CONFIRMED`
2. บันทึก Match ลงฐานข้อมูล
3. ส่ง `MatchConfirmedEvent`
4. `InternshipService.onMatchConfirmed()` รับ Event ด้วย `@EventListener`
5. เรียก `createFromMatch(matchId)`
6. สร้าง Internship สถานะ `NOT_STARTED`
7. บันทึกประวัติการเปลี่ยนสถานะ

ไฟล์ Event:

`demo/src/main/java/com/example/demo/event/MatchConfirmedEvent.java`

Event ประกอบด้วย:

- `matchId`
- `applicationId`
- `positionId`
- `roundId`

Spring ส่ง Event แบบ synchronous ภายใน Transaction เดียวกัน หาก Listener สร้าง Internship ไม่สำเร็จ Exception จะถูกส่งกลับและการยืนยันสิทธิ์จะ Rollback

การสร้าง Internship เป็นแบบ Idempotent หาก Match มี Internship อยู่แล้ว ระบบจะคืนข้อมูลเดิมและไม่สร้างซ้ำ

## Service

### StudentStatusService

หน้าที่หลัก:

- ค้นหาและแบ่งหน้ารายการนักศึกษา
- จำกัดอาจารย์ให้เห็นเฉพาะนักศึกษาที่ตนดูแล
- คำนวณ Stage
- คำนวณ Attention
- แสดงรายละเอียดและ Timeline
- Export CSV แบบ UTF-8 BOM สำหรับ Excel
- ตรวจสิทธิ์ STAFF, ADVISOR และ STUDENT

### InternshipService

หน้าที่หลัก:

- สร้าง Internship หลังยืนยันผลจับคู่
- รับ `MatchConfirmedEvent`
- แก้ไขวันเริ่ม วันสิ้นสุด และข้อมูลผู้ดูแล
- เริ่มฝึกงาน
- เสร็จสิ้นการฝึกงาน
- ยุติการฝึกงาน
- ตรวจสอบ State Transition
- บันทึก Status History
- ส่ง Notification
