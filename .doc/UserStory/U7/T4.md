# U7:T4 Development

User Story U7: นักศึกษาตรวจสอบข้อมูลและสถานะการฝึกงาน/สหกิจศึกษาของตนเอง

## ส่วนที่พัฒนา

### UI

ไฟล์ที่พัฒนา

- `frontend/status.html`
- `frontend/js/status.js`

หน้าเว็บแสดงข้อมูลต่อไปนี้

- รหัสนักศึกษา
- ชื่อ-นามสกุล
- คณะ
- สาขาวิชา
- เกรดเฉลี่ย
- เลขที่คำร้องล่าสุด
- ชื่อแบบฟอร์ม
- สถานะคำร้อง
- วันที่ยื่นคำร้อง
- เหตุผลที่ส่งกลับแก้ไข

สถานะจากระบบถูกแปลเป็นภาษาไทย

| สถานะ | ข้อความที่แสดง |
|---|---|
| DRAFT | ฉบับร่าง |
| SUBMITTED | ยื่นแล้ว รอเจ้าหน้าที่ตรวจสอบ |
| UNDER_REVIEW | รออาจารย์พิจารณา |
| NEED_CORRECTION | ส่งกลับให้แก้ไข |
| APPROVED | อนุมัติแล้ว |
| REJECTED | ไม่อนุมัติ |

### API และ DTO

| API | DTO | การใช้งาน |
|---|---|---|
| `GET /api/students/me` | `StudentProfileResponse` | อ่านข้อมูลนักศึกษาที่ Login |
| `GET /api/requests/me` | `RequestResponse` | อ่านคำร้องของนักศึกษา โดยเรียงรายการล่าสุดก่อน |

ทุก Request ส่ง `X-User-Id` เพื่อระบุผู้ใช้งาน

### Entity และ DAO

| Component | การใช้งาน |
|---|---|
| `Student` | เก็บข้อมูลนักศึกษา |
| `Application` | เก็บข้อมูลคำร้องและสถานะ |
| `StudentRepository` | อ่านข้อมูลนักศึกษา |
| `ApplicationRepository` | อ่านคำร้องของนักศึกษา |
| `findByStudentIdOrderByIdDesc` | อ่านคำร้องโดยเรียงรายการล่าสุดก่อน |

U7 ใช้ Component Backend ร่วมกับ U3 เนื่องจากข้อมูลนักศึกษาและคำร้องถูกเก็บในตารางเดิม

## ลำดับการทำงาน

1. นักศึกษา Login
2. หน้าเว็บอ่าน User ID จาก Session
3. UI เรียก `GET /api/students/me`
4. UI เรียก `GET /api/requests/me`
5. API เรียก Service และ DAO
6. DAO อ่านข้อมูลจากฐานข้อมูล
7. API ส่ง DTO กลับไปยัง UI
8. UI แสดงข้อมูลนักศึกษาและสถานะคำร้องล่าสุด
