# Test Cases Specification – US8 บันทึกการทำงาน (Unit Test: UI + API + DAO + Service)

12 พ.ย. 2026 · ปรับให้ตรงกับ Design (T2: API Spec, DTO, Class / Sequence / ER Diagram) · รวม 73 กรณี (UI 15, API 21, DAO 13, Service 24) · แก้ 13 พ.ย. 2026 ให้สอดคล้องกับ US6 / US7

## ภาพรวมและสมมติฐาน

- นักศึกษาบันทึกงานรายวันของการฝึกงาน (`internshipId`): `logDate`, `startTime`, `endTime`, `activity` (บังคับ), `learning`, `problem` (แต่ละช่องไม่เกิน 2000 ตัวอักษร)
- ระบบคำนวณ `hours` จาก startTime–endTime ต้องได้ 0.5–12 ชั่วโมง · 1 การฝึกงานบันทึกได้ 1 รายการต่อวัน · ห้ามวันในอนาคตหรือนอกช่วงฝึก · การฝึกงานต้อง `IN_PROGRESS`
- สถานะ: `DRAFT → SUBMITTED → APPROVED` · ส่งกลับแก้ไข = `NEED_REVISION` → ส่งใหม่ = `SUBMITTED` · แก้ได้เฉพาะ DRAFT / NEED_REVISION · ลบได้เฉพาะ DRAFT
- ไฟล์แนบต่อบันทึก: `application/pdf`, `image/jpeg`, `image/png` ≤ 10 MB ไม่เกิน 5 ไฟล์ · `lateSubmitted` คำนวณจาก `submitted_at` − `log_date` > 3 วัน (ส่งใหม่คิดจากครั้งล่าสุด)
- ทุก request ส่ง header `X-User-Id` รวมถึงดาวน์โหลดไฟล์แนบ (ไม่รับ `?userId=` ทาง URL) · error ตอบ `{"code": "...", "message": "..."}` · สถานะไม่ถูกต้องใช้ `409 INVALID_STATUS` ชื่อเดียว (ตารางผู้ใช้และ error ของแต่ละ endpoint อยู่ใน [T2 ข้อ 2](T2.md))
- API: 14 endpoint ตาม `us8-01-api-spec.png` (`/api/internships/{id}/work-logs…`, `/api/work-logs/{id}…`, `/api/work-logs/pending-review`, `/review`, `/review-bulk`)
- UI ใช้ mock fetch, API ใช้ mock `WorkLogService` / `WorkLogReviewService`, Service ใช้ mock DAO (Mockito), DAO ทดสอบกับ H2 (โหมด MySQL)
- **ข้อมูลการฝึกงานเป็นข้อมูลจำลอง:** การฝึกงาน (`Internship`) และสถานะของมันเป็นของ US7 ซึ่งยังไม่มีโค้ด ทุก test ที่ใช้การฝึกงาน (เช่น internshipId 7 สถานะ `IN_PROGRESS` ในกลุ่ม UT-SV, UT-RV และ UT-UI) จึงจำลองข้อมูลนี้ด้วย mock (`InternshipDao` / mock fetch) ทดสอบเฉพาะกฎของ US8 ที่ขึ้นกับสถานะ ไม่ได้ทดสอบการสร้างหรือเปลี่ยนสถานะการฝึกงาน (ดู [T2 ข้อ 7](T2.md))
- **ฝั่งอาจารย์ยังไม่มีหน้าเว็บ:** prototype ของ US8 มีเฉพาะหน้านักศึกษา (`worklog.html`) การดูบันทึกรอตรวจ การตรวจ และการอนุมัติหลายรายการ (UC8-6 ถึง UC8-8) จึงไม่มี UI test ทดสอบที่ API (UT-API-18–20) และ Service (UT-RV-01–07) แทน เมื่อทำหน้าอาจารย์แล้วต้องเพิ่ม UI test ของหน้านั้น
