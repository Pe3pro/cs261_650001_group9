# Requirement – US8 บันทึกการทำงาน

## User Story

| ID | User Story |
|---|---|
| US8-a | ในฐานะ**นักศึกษา** ฉันต้องการบันทึกงานที่ทำในแต่ละวันพร้อมเวลาเริ่ม–สิ้นสุด เพื่อเก็บหลักฐานการฝึกและไม่ต้องเขียนสมุดบันทึกด้วยมือ |
| US8-b | ในฐานะ**นักศึกษา** ฉันต้องการเห็นชั่วโมงสะสม จำนวนวันที่บันทึกเทียบกับวันทำงาน และวันที่ยังขาดบันทึก เพื่อวางแผนการฝึกได้ |
| US8-c | ในฐานะ**อาจารย์ที่ปรึกษา** ฉันต้องการอ่านบันทึกของนักศึกษาในที่ปรึกษา อนุมัติหรือส่งกลับแก้ไขพร้อมความเห็น เพื่อติดตามความก้าวหน้าระหว่างฝึก |
| US8-d | ในฐานะ**เจ้าหน้าที่** ฉันต้องการดูบันทึกและสรุปชั่วโมงของการฝึกงานแต่ละรายการ และส่งออกเป็นไฟล์ได้ เพื่อติดตามได้ทันก่อนจบการฝึก |

## Stakeholder

| Stakeholder | ต้องการ | Pain point ตอนนี้ |
|---|---|---|
| นักศึกษา | บันทึกงานรายวัน (เวลาเริ่ม–สิ้นสุด งานที่ทำ สิ่งที่ได้เรียนรู้ ปัญหา) แนบหลักฐาน เห็นชั่วโมงสะสมและวันที่ขาดบันทึก | เขียนสมุดด้วยมือ ไฟล์หาย นับชั่วโมงเอง ไม่รู้ว่าครบหรือยัง |
| อาจารย์ที่ปรึกษา | อ่านบันทึกของนักศึกษาในที่ปรึกษา (ต่อจาก US7) อนุมัติ / ส่งกลับแก้ไข ทีละรายการหรือหลายรายการพร้อมกัน | ได้เห็นสมุดตอนจบการฝึกครั้งเดียว ติดตามระหว่างทางไม่ได้ |
| เจ้าหน้าที่ | ดูบันทึกและสรุปชั่วโมงของแต่ละการฝึกงาน ส่งออกบันทึกเป็นไฟล์ | ตรวจนับชั่วโมงจากสมุดทีละเล่ม รู้ว่าชั่วโมงไม่ครบเมื่อสายไป |
| บริษัท / พี่เลี้ยง | รับรองการทำงานโดยเซ็นใบลงเวลา นักศึกษาเป็นผู้อัปโหลดเป็นไฟล์แนบ (ไม่ได้ใช้ระบบ) | — |

## สถานะบันทึกการทำงาน

| สถานะ | ความหมาย | เกิดจาก |
|---|---|---|
| DRAFT | บันทึกร่าง แก้ไข / ลบได้ อาจารย์และเจ้าหน้าที่ยังไม่เห็น | UC8-1 |
| SUBMITTED | ส่งแล้ว รออาจารย์ตรวจ แก้ไขไม่ได้ | UC8-2 |
| NEED_REVISION | อาจารย์ส่งกลับให้แก้ไข (มีความเห็นเสมอ) แก้แล้วส่งใหม่เป็น SUBMITTED | UC8-7 |
| APPROVED | อาจารย์อนุมัติแล้ว แก้ไขไม่ได้ | UC8-7, UC8-8 |

`DRAFT → (นักศึกษาส่ง) SUBMITTED → (อาจารย์อนุมัติ) APPROVED` · ส่งกลับแก้ไข `SUBMITTED → NEED_REVISION → (แก้แล้วส่งใหม่) SUBMITTED`

## กฎทางธุรกิจ

| รหัส | กฎ |
|---|---|
| BR8-1 | บันทึกได้เมื่อการฝึกงาน (US7) มีสถานะ `IN_PROGRESS` และเป็นการฝึกงานของนักศึกษาคนนั้นเอง |
| BR8-2 | `logDate` ต้องอยู่ในช่วง `start_date`–`end_date` ของการฝึกงาน และไม่เป็นวันในอนาคต |
| BR8-3 | 1 การฝึกงาน บันทึกได้ 1 รายการต่อวัน (unique `internship_id + log_date`) |
| BR8-4 | ชั่วโมงคำนวณจาก `startTime`–`endTime` (เวลาสิ้นสุดต้องหลังเวลาเริ่ม) ต้องได้ 0.5–12 ชั่วโมง |
| BR8-5 | `activity` (งานที่ทำ) บังคับกรอก · `learning`, `problem` ไม่บังคับ · แต่ละช่องไม่เกิน 2000 ตัวอักษร |
| BR8-6 | ไฟล์แนบผูกกับบันทึกแต่ละวัน: ชนิด `application/pdf`, `image/jpeg`, `image/png` (นามสกุล .pdf .jpg .jpeg .png) ไฟล์ละไม่เกิน 10 MB ไม่เกิน 5 ไฟล์ต่อบันทึก |
| BR8-7 | แก้ไข / แนบไฟล์ / ลบไฟล์แนบ ได้เฉพาะ `DRAFT` และ `NEED_REVISION` · ลบบันทึกได้เฉพาะ `DRAFT` |
| BR8-8 | ส่งหลังวันที่บันทึกเกิน 3 วัน ระบบติดป้าย "ส่งล่าช้า" แต่ยังส่งได้ · `lateSubmitted` ไม่ได้เก็บเป็นคอลัมน์ คำนวณทุกครั้งจาก `submitted_at` − `log_date` > 3 วัน · การส่งแต่ละครั้งเขียนทับ `submitted_at` ดังนั้นบันทึกที่ถูกส่งกลับแก้ไขแล้วส่งใหม่ จะคิดล่าช้าใหม่จากวันที่ส่งครั้งล่าสุด |
| BR8-9 | ส่งกลับแก้ไขต้องมีความเห็นเสมอ · อนุมัติหลายรายการได้ครั้งละไม่เกิน 100 รายการ |
| BR8-10 | ชั่วโมงสะสมนับเฉพาะบันทึกที่ไม่ใช่ `DRAFT` · วันทำงาน = วันจันทร์–ศุกร์ ตั้งแต่วันเริ่มฝึกถึงวันนี้ (หรือวันสิ้นสุดการฝึก) · **ข้อจำกัด:** ยังไม่หักวันหยุดราชการและวันหยุดของบริษัท วันหยุดเหล่านี้จึงแสดงเป็นวันที่ขาดบันทึก |
| BR8-11 | สิทธิ์: นักศึกษาเห็นเฉพาะการฝึกงานของตน · อาจารย์เห็นเฉพาะนักศึกษาในที่ปรึกษาและไม่เห็น `DRAFT` · เจ้าหน้าที่เห็นทุกการฝึกงาน (ยกเว้น `DRAFT`) |

## Use case

| UC | ชื่อ | ผู้ทำ | เงื่อนไขก่อน | ขั้นตอนหลัก | ผลลัพธ์ | API |
|---|---|---|---|---|---|---|
| UC8-1 | บันทึกการทำงานรายวัน | นักศึกษา | BR8-1, BR8-2, BR8-3 | เลือกวันที่ → กรอกเวลาเริ่ม–สิ้นสุด (ระบบคำนวณชั่วโมง) งานที่ทำ สิ่งที่ได้เรียนรู้ ปัญหา → "บันทึกแบบร่าง" | บันทึก `DRAFT` | `POST /api/internships/{id}/work-logs` |
| UC8-2 | ส่งบันทึกให้อาจารย์ตรวจ | นักศึกษา | บันทึก `DRAFT` หรือ `NEED_REVISION` | กด "ส่งบันทึก" (จากฟอร์มจะสร้างแล้วส่งต่อทันที) | `SUBMITTED` + แจ้งเตือนอาจารย์ที่ปรึกษา (`WORK_LOG_SUBMITTED`), คำนวณ `lateSubmitted` | `POST /api/work-logs/{id}/submit` |
| UC8-3 | แก้ไข / ลบบันทึก | นักศึกษา | BR8-7 | เปิดบันทึกจากประวัติ → แก้ไขแล้วบันทึก หรือ ลบ → ยืนยัน | บันทึกถูกแก้ (ชั่วโมงคำนวณใหม่) หรือถูกลบพร้อมไฟล์แนบ | `PUT` / `DELETE /api/work-logs/{id}` |
| UC8-4 | แนบใบลงเวลา / หลักฐาน | นักศึกษา | บันทึกนั้นเป็น `DRAFT` หรือ `NEED_REVISION`, BR8-6 | เลือกไฟล์ → อัปโหลด (ลบไฟล์ที่แนบแล้วได้) | ไฟล์ผูกกับบันทึกวันนั้น อาจารย์และเจ้าหน้าที่ดาวน์โหลดได้ | `POST` / `GET` / `DELETE /api/work-logs/{id}/attachments[/{attachmentId}]` |
| UC8-5 | ดูบันทึกและสรุปชั่วโมง | นักศึกษา / อาจารย์ / เจ้าหน้าที่ | BR8-11 | เปิดหน้าบันทึก → กรองช่วงวันที่ / สถานะ → เปิดดูรายละเอียด | รายการเรียงตามวันที่พร้อมสถานะ ป้ายส่งล่าช้า ความเห็นอาจารย์ และสรุป: ชั่วโมงรวม วันที่บันทึก / วันทำงาน วันที่ขาดบันทึก จำนวนแต่ละสถานะ | `GET /api/internships/{id}/work-logs`, `…/summary`, `GET /api/work-logs/{id}` |
| UC8-6 | ดูบันทึกรอตรวจ | อาจารย์ที่ปรึกษา | — | เปิดหน้า "บันทึกรอตรวจ" | รายการ `SUBMITTED` ของนักศึกษาในที่ปรึกษา | `GET /api/work-logs/pending-review` |
| UC8-7 | ตรวจและให้ความเห็น | อาจารย์ที่ปรึกษา | บันทึก `SUBMITTED` ของนักศึกษาในที่ปรึกษา | อ่านบันทึก → เลือก "อนุมัติ" (`APPROVE`) หรือ "ส่งกลับแก้ไข" (`REVISE`) → กรอกความเห็น (บังคับเมื่อ REVISE) → ยืนยัน | `APPROVED` หรือ `NEED_REVISION` + แจ้งเตือนนักศึกษา (`WORK_LOG_REVIEWED`) | `POST /api/work-logs/{id}/review` |
| UC8-8 | อนุมัติหลายบันทึกพร้อมกัน | อาจารย์ที่ปรึกษา | เลือก 1–100 บันทึก | เลือกบันทึก → "อนุมัติที่เลือก" | บันทึกที่ผ่านเงื่อนไขเป็น `APPROVED` ที่ไม่ผ่านอยู่ใน `skipped` พร้อมเหตุผล | `POST /api/work-logs/review-bulk` |
| UC8-9 | ส่งออกบันทึก | อาจารย์ / เจ้าหน้าที่ | มีสิทธิ์ดูการฝึกงานนั้น | กด "ส่งออก" | ไฟล์ CSV (`text/csv`) บันทึกทั้งหมดที่ไม่ใช่ DRAFT เปิดด้วย Excel ได้ | `GET /api/internships/{id}/work-logs/export` |

## นอกขอบเขตรอบนี้ (ยังไม่มีใน Design)

| เรื่อง | เหตุผล / ทำต่อที่ไหน |
|---|---|
| ชั่วโมงขั้นต่ำที่ต้องฝึก และการตั้งค่าเกณฑ์ (`minHours`, `reminderDays`) | ยังไม่มี API ตั้งค่าและ field ใน `WorkLogSummaryResponse` · ตอนนี้ US8-b เทียบกับวันทำงานแทน |
| หน้าเจ้าหน้าที่ติดตามทุกคน + ส่งแจ้งเตือนคนขาดส่ง | **แผนในอนาคต** รอ US7 (ยังไม่มีในโปรเจกต์): ออกแบบไว้ให้ US7 แสดงผ่าน `StudentStatusResponse.attention` (`MISSING_LOG`, `LOG_PENDING`) · ตอนนี้ US8 เตรียมไว้แค่ `WorkLogService.hasPendingReview()` ให้ US7 เรียกใช้ |
| ส่งออกสมุดบันทึกเป็น PDF และให้นักศึกษาส่งออกเอง | ตอนนี้ส่งออกเป็น CSV สำหรับอาจารย์ / เจ้าหน้าที่ |
| รายงานประจำเดือน | ไม่มี use case และ API รองรับ |
| วันหยุดราชการ / วันหยุดของบริษัท | ต้องมีตารางวันหยุดก่อน จึงจะหักออกจากวันทำงานใน BR8-10 ได้ |
