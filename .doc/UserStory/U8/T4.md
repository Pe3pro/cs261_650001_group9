ความสามารถของหน้า:

- กรอกวันที่ เวลาเริ่ม–สิ้นสุด (คำนวณชั่วโมงให้อัตโนมัติ) งานที่ทำ สิ่งที่ได้เรียนรู้ ปัญหา และแนบไฟล์รูป / PDF
- ตรวจข้อมูลก่อนส่ง: วันที่ไม่เป็นอนาคตและอยู่ในช่วงฝึก, ชั่วโมง 0.5–12, ไฟล์ JPG/PNG/PDF ไม่เกิน 10 MB และไม่เกิน 5 ไฟล์
- ปุ่ม "บันทึกแบบร่าง" (DRAFT) และ "ส่งบันทึก" (SUBMITTED); ส่งหลังวันที่ทำงานเกิน 3 วันแสดง "ส่งล่าช้า"
- เปิดบันทึกเดิมจากประวัติ: แก้ได้เฉพาะ DRAFT / NEED_REVISION, ลบได้เฉพาะ DRAFT, แสดงความเห็นอาจารย์
- การ์ดสรุป: ชั่วโมงสะสม, วันที่บันทึก / วันทำงาน, วันที่ขาดบันทึก

## 2. การรวมโค้ดตาม Sequence Diagram

| Sequence Diagram | ลำดับในโค้ด |
|---|---|
| นักศึกษาบันทึก แนบไฟล์ และส่งบันทึก | `create`: `internshipDao.findById` → ไม่ใช่ของตน 403 → ไม่ IN_PROGRESS 409 → ข้อมูลผิด 400 → `existsByInternshipIdAndLogDate` 409 → `calcHours` → `save(DRAFT)` · `addAttachment`: `countByWorkLogId` → ตรวจไฟล์ → `fileStorage.store("work-logs/{id}")` → `save(attachment)` · `submit`: `findById` → สถานะไม่ใช่ DRAFT / NEED_REVISION 409 → `save(SUBMITTED, submittedAt)` → `notifyWorkLogSubmitted` |
| อาจารย์ตรวจบันทึกการทำงาน | `getPending` → `findSubmittedByAdvisorId` · `review`: ตรวจผู้ใช้ → `findById` → `checkAdvisor` 403 → ไม่ใช่ SUBMITTED 409 → REVISE ไม่มีความเห็น 400 → `save(APPROVED / NEED_REVISION)` → `notifyWorkLogReviewed` · `reviewBulk` ทำทีละบันทึก ที่ไม่ผ่านใส่ `skipped` |

## 3. ส่วนที่ต่างจากการออกแบบ / ข้อจำกัด

- **ยังไม่มีโค้ดของ US7**: จึงสร้าง `Internship` (ตาราง `internships`), `InternshipStatus` และ `InternshipDao` เฉพาะส่วนที่ US8 ใช้ โดยใช้ชื่อเดียวกับที่ US7 ออกแบบไว้ (ตอน merge ใช้ไฟล์ของ US7 แทน ดู [T2 ข้อ 7](T2.md)) และเพิ่ม `GET /api/work-logs/my-internship` ให้หน้าเว็บหา internshipId ได้ ส่วน `StudentStatusService` / `InternshipService` (extended) และค่า `MISSING_LOG`, `LOG_PENDING` ยังไม่ได้ทำ แต่เตรียม `WorkLogService.hasPendingReview()` ไว้ให้ US7 เรียกแล้ว
- **`WorkLogDetailResponse`** เขียนเป็น record ที่มี field ของ `WorkLogResponse` ครบ เพราะ record สืบทอดกันไม่ได้ (JSON ออกมาเหมือนกัน)
- **UI ตาม prototype เดิมเป็นรายสัปดาห์และมีรายงานประจำเดือน**: ปรับเป็นบันทึกรายวันตาม API Spec / DTO และตัดส่วนรายงานประจำเดือนออก เพราะไม่มี API รองรับ (อัปเดตรูป prototype ใน T2 เป็นหน้ารายวันแล้ว)
- **หน้าอาจารย์ตรวจบันทึก**: มี API ครบ แต่ยังไม่ได้ทำหน้า UI (prototype มีเฉพาะหน้านักศึกษา)
- **ฐานข้อมูลเดิม (แก้แล้ว)**: ฐานข้อมูลที่สร้างก่อน US8 มีคอลัมน์ `notifications.type` เป็น ENUM ของ MySQL ค่าใหม่ `WORK_LOG_*` จึงบันทึกไม่ได้ (`Data truncated for column 'type'` → `POST /api/work-logs/{id}/submit` ได้ 500 ตอนรัน Postman รอบแรก) แก้โดย `Notification.type` เก็บเป็น `VARCHAR(50)` (`@JdbcTypeCode(SqlTypes.VARCHAR)`) และเพิ่ม `config/LegacySchemaFixer` เปลี่ยนคอลัมน์เดิมเป็น VARCHAR ให้อัตโนมัติตอนเริ่มระบบ (เฉพาะ MySQL) ไม่ต้องลบ volume ของฐานข้อมูล
