User story
-
- **As a** นักศึกษา
- **I want to** ค้นหารายชื่อบริษัท MOU จัดลำดับความต้องการ (Ranking) และตรวจสอบโควตารับสมัคร
- **So that** สามารถสมัครเข้าฝึกงานในบริษัทที่ต้องการได้อย่างเป็นระบบ

ผู้ใช้และสิทธิ์
-
| ผู้ใช้ (role) | ทำอะไรได้ | หน้าเว็บ |
|---|---|---|
| นักศึกษา (STUDENT) | ดูบริษัทและตำแหน่งที่เปิดรับพร้อมจำนวนที่ว่าง · จัดอันดับตำแหน่ง 1–5 · ดูผลการจับคู่ของตนเอง · ยืนยันสิทธิ์ / สละสิทธิ์ | `matching.html` |
| เจ้าหน้าที่ (STAFF) | จัดการบริษัท ตำแหน่ง และโควตา · เปิดรอบ · จับคู่อัตโนมัติ / จับคู่เอง / ยกเลิกผล · ประกาศผล | `staff-matching.html` |

ทุกคน login ที่ `login.html` (U1) ก่อน · role มาจาก backend ไม่ต้องเลือกเอง

ขั้นตอนการทำงาน
-
1. เจ้าหน้าที่เพิ่มบริษัท และเพิ่มตำแหน่งพร้อมโควตาของแต่ละบริษัท
2. นักศึกษาที่ใบสมัครได้รับอนุมัติ (`APPROVED`) ดูรายชื่อบริษัทที่เปิดรับพร้อมจำนวนที่ว่าง แล้วบันทึกตำแหน่งที่สนใจ 1–5 อันดับ
3. เจ้าหน้าที่เปิดรอบการจับคู่ใหม่ (ทีละรอบ) พร้อมกำหนด `confirmDeadline`
4. เจ้าหน้าที่สั่งจับคู่อัตโนมัติตามอันดับและโควตาในรอบปัจจุบัน · ใบที่จับไม่ได้แสดงพร้อมเหตุผล · จับคู่เองทีละใบ หรือยกเลิกผล (คืนโควตา) ได้
5. เจ้าหน้าที่ประกาศผลรอบ → ระบบอัปเดตผลทุกอันดับ และแจ้งเตือนนักศึกษาทุกคนในรอบ
6. นักศึกษาดูผลการจับคู่ แล้วยืนยันสิทธิ์ หรือสละสิทธิ์ (ต้องมีเหตุผล) ภายใน `confirmDeadline` · สละสิทธิ์แล้วคืนโควตา
7. เมื่อเลย `confirmDeadline` เจ้าหน้าที่เปิดรอบถัดไป → ระบบปิดรอบเก่า ผลที่ยังไม่ตอบถือว่าสละสิทธิ์ (คืนโควตา) · นักศึกษาที่ยังไม่ได้ที่ฝึกแก้อันดับใหม่ได้

กฎของระบบ
-
| หัวข้อ | กฎ |
|---|---|
| การจัดอันดับ | เลือก**ตำแหน่ง** 1–5 อันดับ (อย่างน้อย 1 ไม่ซ้ำ ตำแหน่งต้องเปิดรับ) · บันทึกใหม่แทนที่ของเดิมทั้งหมด · ใบสมัครต้อง `APPROVED` และยังไม่มีผลจับคู่ `PROPOSED` / `CONFIRMED` |
| โควตา | เก็บที่ระดับตำแหน่ง (`availableSlots`) · จับคู่ลด 1 · สละสิทธิ์ / ยกเลิกคืน 1 · ลดโควตาให้ต่ำกว่าจำนวนที่จับคู่แล้วไม่ได้ |
| รอบการจับคู่ | `OPEN` → (ประกาศผล) `ANNOUNCED` → `CLOSED` · เปิดได้ทีละรอบ · เปิดรอบใหม่ได้เมื่อรอบก่อนประกาศผลและเลย `confirmDeadline` แล้ว (ระบบปิดรอบเก่าให้) · จับคู่ได้เฉพาะรอบที่ `OPEN` |
| การจับคู่อัตโนมัติ | ไล่ใบสมัคร `APPROVED` ที่ยังไม่มีผล ตามเวลายื่น · แต่ละใบไล่อันดับ 1 → 5 จนเจอตำแหน่งที่ยังมีที่ว่าง · ใบที่จับไม่ได้คืนกลับมาพร้อมเหตุผล |
| การยกเลิกผล | เจ้าหน้าที่ยกเลิกผล `PROPOSED` / `CONFIRMED` ได้ · สถานะเป็น `CANCELLED` และคืนโควตา |
| การประกาศผล | อัปเดตผลทุกอันดับ และแจ้งเตือนนักศึกษาทุกคนในรอบ · ก่อนประกาศ นักศึกษาดูผลไม่ได้ (404) |
| การตอบรับ | ยืนยัน / สละสิทธิ์ได้เฉพาะเจ้าของผลที่ยัง `PROPOSED` · สละสิทธิ์ต้องมีเหตุผล · ต้องตอบก่อน `confirmDeadline` · ไม่ตอบภายในกำหนดถือว่าสละสิทธิ์ |
| ความสัมพันธ์กับ U4 | การจัดอันดับบริษัทของ U4 (ก่อนยื่นคำร้อง) ยังใช้เหมือนเดิม ไม่ใช่ข้อมูลที่ใช้จับคู่ |

Acceptance criteria (test case หลักของ U6)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 | นักศึกษาที่ใบสมัคร `APPROVED` เห็นบริษัทที่เปิดรับพร้อมจำนวนที่ว่าง และบันทึกอันดับ 1–5 ได้ |
| TC2 | บันทึกอันดับไม่ได้ เมื่อใบสมัครยังไม่ `APPROVED` หรือมีผลจับคู่แล้ว หรือเลือก 0 / เกิน 5 อันดับ / ซ้ำ |
| TC3 | เจ้าหน้าที่เพิ่ม / แก้บริษัทและตำแหน่งพร้อมโควตาได้ · ลดโควตาต่ำกว่าจำนวนที่จับคู่แล้วไม่ได้ |
| TC4 | เจ้าหน้าที่เปิดรอบ แล้วจับคู่อัตโนมัติตามอันดับและโควตาได้ · ใบที่จับไม่ได้มีเหตุผล · จับคู่เองและยกเลิกผล (คืนโควตา) ได้ |
| TC5 | ประกาศผลรอบแล้ว นักศึกษาทุกคนในรอบได้รับแจ้งเตือน และเห็นผลทุกอันดับ |
| TC6 | นักศึกษายืนยันหรือสละสิทธิ์ (ต้องมีเหตุผล คืนโควตา) ได้ก่อน `confirmDeadline` · เลยกำหนดแล้วตอบไม่ได้ · ก่อนประกาศผลดูผลไม่ได้ |
| TC7 | ผู้ใช้ที่ไม่มีสิทธิ์ถูกปฏิเสธ: นักศึกษาเรียก API ของเจ้าหน้าที่ · ดูหรือแก้อันดับ / ผลของคนอื่น |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role` (ทุก request ส่ง `X-User-Id`)
- U3 / U5 คำร้อง: ใบสมัครต้องผ่านการอนุมัติจนเป็น `APPROVED` ก่อน
- U4 จัดอันดับบริษัท: มีตาราง `companies`, `company_positions`, `company_rankings` และ API จัดอันดับอยู่แล้ว (ดู [Task2 · ส่วนที่ 4](T2.md))
- U5 การแจ้งเตือน: ใช้ระบบแจ้งเตือนเดิม (`/api/notifications`) ตอนประกาศผล
